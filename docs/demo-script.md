# 招牌演示脚本（5H）

> 目标：60-90 秒一镜到底（或分镜剪辑），把 GateSQL 的差异化讲清楚。
> 录制工具：Windows 自带 `Win + G`（Xbox Game Bar）即可，或 OBS；1080p、浏览器缩放 110%。
> 录制前检查：`pnpm dev` 已起、`data/shop.db` 与 `data/app.db` 在位、提问前清空输入框。
>
> **纪律**：演示里的每个画面都已实测可复现；不要现场即兴换问法（换问法 = 换 cassette 键 = 现场真调，又慢又有随机性）。

---

## 镜头 1 · 一个数字的"验明正身"（约 25 秒）

**输入**：`我们店铺总共卖了多少钱？`

等待答案出来（约 8-10 秒，live 模式真调；replay 模式秒回）。

**口播**：*"一般的 Text-to-SQL 到这里就结束了。我们多给三样东西。"*

镜头依次指给观众看（可用鼠标圈画）：

1. **三态徽章**——「已核验」绿色标签：这个数字通过了安全/口径/体检三层检查；
2. **口径回执卡**——「已排除（实测计数）：已取消 1873 单、已退款 2017 单」。口播：*"这两个数不是模型说的，是程序拿着 SQL 的语法树去数据库现场数的——模型碰不到这张卡片。"*
3. **历史回放链接**。

## 镜头 2 · 拒答也是产品（约 15 秒）

**输入**：`我们的利润率怎么样？`

**预期**：秒回（0 模型调用），红色拒答卡 + 三个澄清选项（毛利口径 / 退款影响 / 净利口径）。

**口播**：*"利润率有三种算法，先问清楚再算——这个澄清是确定性词典实现的，不赌模型自觉。"*

点击「毛利口径」选项 → **自动带口径重新提问**（多轮澄清：原问题 + 澄清话术拼回，第二轮经词典 disambiguator 放行），直接出毛利口径的结果——手不碰键盘。

## 镜头 3 · 空结果不说谎（约 15 秒）

**输入**：`2027 年 1 月的已完成订单销售额是多少？`

**预期**：秒回**拒答**（A4 提前拒答闸门第二道子检查：时间窗口整体越过数据水位，0 次模型调用），理由「你问的时间范围（2027-01-01 ~ 2027-01-31）在数据覆盖范围（截至 2026-08-31）之外，无数据可查」+ 可查表清单。

**口播**：*"问了一个数据库里还不存在的月份——系统在调模型之前就发现了，一次 API 都不花。部分重叠的情况（比如'近 30 天'跨过水位线）则照常计算，由结果体检查出'末端数据不完整'并画出虚线——两种情况两种诚实。"*

## 镜头 4 · 自愈过程可回放（约 20 秒，不用现场跑）

打开 `/runs` 里挑一条带「第 1 次尝试 / 第 2 次尝试」的历史记录（如 `r_0ac721b1`），展开：

- SQL 尝试的**左右 diff**（红删绿增）；
- **执行追踪面板**：每次调用的完整 prompt、检查结论、各阶段耗时。

**口播**：*"它被口径规则拦下后自己修好了——全过程存档，事后可以逐步回放。trace 里存着每次发给模型的完整原文。"*

## 镜头 5 · 报表固化（约 15 秒）

聊天页点「存为报表」→ 打开 `/reports` → 点开报表：

**预期**：绿色「0 次模型调用」徽章 + 毫秒级耗时 + 结果。

**口播**：*"答对的 SQL 固化下来，以后重算零成本、结果永远一致；答错的还可以人工改对回流成 few-shot 教材——系统越用越准。"*

## 收尾一句话（口播）

*"这就是 GateSQL：不仅给出数字，还给得出**这个数字凭什么可信**的证据链。30 题六层评测集上准确率 100%，规则引擎误报 0%，全部有 A/B 数据背书。"*

---

## 备用素材（第 6 周用）

- **无 key 演示**：不设 API key 时全程 replay（第 6 周接入预置问题清单后录制）；
- **截图清单**（用于 README/GitHub）：回执卡片特写、追踪面板展开态、空结果归因横幅、/reports 重跑页。

## 已知边界（演示时如被问到）

- 现场新问法会真调模型（10 秒左右）——演示脚本里的问法都有 cassette 或词典兜底；
- 「自愈」现场复现不稳定（模型现在一次写对的概率很高）——所以镜头 4 用历史存档回放，这正是 trace 存在的意义。
