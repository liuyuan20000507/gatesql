# 开发路线图

每个任务都有**完成标准**。标准没达到就不要往下走，否则后面会返工。
做完一项就把 `[ ]` 改成 `[x]`，你能看到进度，AI 也能知道现在做到哪了。

---

## 第 0 周：准备（半天，今天就能做完）

- [ ] **装依赖**
  - 后端：`pip install fastapi uvicorn[standard] openai python-dotenv sse-starlette`
  - 前端：`cd frontend` 然后 `pnpm create next-app@latest . --typescript --tailwind --app`
  - 完成标准：两条命令都不报错

- [ ] **生成示例数据库**
  - 运行 `python scripts/seed_db.py`
  - 完成标准：`data/shop.db` 文件存在，用工具打开能看到 4 张表有数据

- [ ] **确认大模型能调通**
  - 写一个 10 行的脚本，调一次模型让它回答「你好」
  - 完成标准：能打印出模型的回复。**这一步不通就别往下做**，后面全建立在它上面

- [ ] **git 初始化**
  - `git init` 然后提交一次
  - 完成标准：`git log` 能看到第一条提交记录

---

## 第 1 周：骨架先通（不碰大模型）

本周唯一目标：**前后端能通、流式能动**。很多人卡在这里，先解决掉。

- [ ] **后端假接口**
  - 实现 `POST /api/chat`，不调模型不查库，按 `docs/03-api-contract.md` 的顺序推写死的事件，每个事件间隔 0.3 秒
  - 实现 `GET /api/health` 和 `GET /api/schema`（schema 可以先返回写死的数据）
  - 完成标准：用 `curl -N http://localhost:8000/api/chat -X POST -H "Content-Type: application/json" -d "{\"question\":\"测试\"}"` 能看到事件一个个冒出来，不是一次性全出来

- [ ] **前端对话界面**
  - 输入框 + 消息列表 + 发送按钮
  - 封装 SSE 客户端，能接收并分类处理事件
  - 状态提示、SQL 展示区、表格、文字结论四个区域
  - 完成标准：在浏览器里提问，能看到状态一步步变化、SQL 出现、表格出现、结论一个字一个字打出来

- [ ] **打通跨域**
  - 后端配 CORS 允许 `localhost:3000`
  - 完成标准：浏览器控制台没有 CORS 报错

**本周结束时**：你有一个看起来完整能用的网站，只是数据是假的。这个里程碑很重要 —— 剩下的工作全是「把假的换成真的」，心理压力小很多。

---

## 第 2 周：Agent 核心（项目最重要的一周）

- [ ] **提取表结构**
  - 从 SQLite 读出表名、字段名、类型，拼成模型能读懂的文本
  - 完成标准：打印出来的表结构描述，你自己读一遍能看懂

- [ ] **SQL 安全检查（自己写，别交给 AI）**
  - 实现 `docs/02-architecture.md` 里那五层防护
  - 完成标准：写 10 个恶意输入的测试用例全部被拦下，包括 `SELECT 1; DROP TABLE orders`

- [ ] **只读执行 SQL**
  - SQLite 用只读模式连接，带超时和行数上限
  - 完成标准：尝试执行 `DELETE FROM orders` 会抛异常，且数据库行数不变

- [ ] **Agent 主循环（自己写，别交给 AI）**
  - 按架构文档里那六步实现，含重试机制
  - 完成标准：问「一共有多少个客户」能拿到正确数字；故意问一个会写错 SQL 的问题，日志里能看到重试并最终成功

- [ ] **把假接口换成真的**
  - 完成标准：前端一行代码都不用改，就能查到真实数据。如果需要改前端，说明接口约定没遵守，回去对照文档

**本周结束时**：项目真正跑起来了。这一周的代码是你面试时要讲的东西，务必自己写、自己懂。

## 第 3 周：产品化

- [ ] **图表自动选型**
  - 让模型在总结时同时输出图表建议，前端用 ECharts 渲染
  - 完成标准：问趋势类问题出折线图，问对比类问题出柱状图，问占比出饼图

- [ ] **表结构侧边栏**
  - 前端展示可查询的表和字段，用户知道能问什么
  - 完成标准：点击表名能展开看到字段列表

- [ ] **历史记录**
  - 提问历史存起来，可以点回去看
  - 完成标准：刷新页面后历史还在

- [ ] **错误处理完善**
  - 五种 error code 前端都有对应的友好提示
  - 完成标准：手动触发每一种错误，界面都不会白屏或卡在加载中

- [ ] **schema 裁剪**
  - 表多的时候先让模型选相关表，再只给那几张的结构
  - 完成标准：日志里能看到「本次只提供了 orders / order_items 两张表」这类记录

## 第 4 周：评测和调优（简历数字的来源）

- [ ] **建测试集**
  - 按 `docs/01-requirements.md` 的分层，写 50 道题和标准答案到 `data/evalset.jsonl`
  - 完成标准：文件有 50 行，每行都能被 json 正确解析

- [ ] **写评测脚本**
  - 批量跑测试集，对比执行结果，输出准确率、平均重试次数、平均耗时
  - 完成标准：一条命令跑完全部 50 题并打印汇总报告

- [ ] **跑基线**
  - 记录第一次的成绩到 `docs/eval-log.md`
  - 完成标准：有一个初始准确率数字（大概率在 60-75% 之间，低不代表你做得差）

- [ ] **至少做三轮优化**
  - 每轮改一个地方，重新跑，记录变化。常见有效手段：给字段加中文注释、提示词里加几个示例、SQL 生成后先做一次自检、schema 裁剪
  - 完成标准：`docs/eval-log.md` 里有至少四条记录（基线 + 三轮），能看出准确率的提升轨迹

**本周结束时**：你有了简历上那句话 ——「通过 XXX 手段将准确率从 XX% 提升到 XX%」。

## 第 5 周：上线和收尾

- [ ] **Docker Compose**
  - 前后端各一个容器，一条 `docker compose up` 全起来
  - 完成标准：在一台干净的机器上克隆项目就能跑起来

- [ ] **部署到公网**
  - 云服务器或免费平台都行
  - 完成标准：手机上打开链接能用

- [ ] **写 README**
  - 必须包含：一句话介绍、演示 GIF、架构图、技术栈、本地启动步骤、评测结果表格、踩坑记录
  - 完成标准：找一个不了解这个项目的人读一遍，他能说出这个项目是干什么的、以及怎么跑起来

- [ ] **踩坑记录**
  - 把开发过程中卡住超过半小时的问题都写下来，怎么发现、怎么解决
  - 完成标准：至少 5 条。这部分面试官最爱看，因为能看出你真的做过

## 如果卡住了怎么办

1. **先看完成标准** —— 你是不是在做标准之外的事？范围蔓延是新手最大的时间黑洞
2. **拆到 30 分钟能做完的粒度** —— 「实现 agent 循环」太大，「让模型输出一段 SQL 并打印出来」就刚好
3. **卡超过 1 小时就记下来先跳过** —— 写进 `docs/blocked.md`，做别的，往往第二天自己就通了
4. **别同时改两个地方** —— 一次只动一处，坏了才知道是哪一下坏的
