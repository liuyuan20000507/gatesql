# ADR-016 · 环路检测指纹：语义归一边界

**背景**：防模型震荡需要给每条 SQL 算指纹；「语义等价」的水深不见底。

**决策**：只认两条**可证明安全**的等价——①AND/OR 操作数排序（交换律，无条件成立）；②列引用别名归约为真实表名。**明确不碰**：JOIN 顺序（内连接等价但外连接不等价，AST 分不清）、`x<=5` vs `x<6`（依赖「x 是数值」前提）、子查询↔JOIN 改写。

**关键问题**：**误杀比漏抓代价大**——漏抓只是多烧几轮预算（文本指纹和预算计数器兜底）；误杀会把模型真实的改动当成震荡掐死，过早终止可能正确的方向。

**护栏**：AND 叶子按整条序列化排序——操作数集合不同（哪怕只换值）就是不同指纹，`a=1 AND b=2` 与 `a=2 AND b=1` 不会合并。

**代价**：`x<=5`↔`x<6`、子查询改写类的震荡仍抓不到——有 execRetries 和 repairs 兜底，可接受。7 单测锁死边界。
