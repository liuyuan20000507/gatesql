# ADR-022 · 列名静态核对：零误报纪律

**背景**：模型偶尔幻觉列名（created_at 写成 order_date），以前靠执行时数据库报错 + execRetries 回炉，反馈只有冷冰冰的 `no such column`。

**决策**：lint 之后、EQP 之前插入步骤 5.5——把 AST 里**带真实表前缀**的列引用对照 PRAGMA 实际列清单；错列在执行前拦下，诊断精确到「该表可用列清单」。

**关键问题**：新增检查层最大的风险不是漏，是**误杀**——白烧预算 + 冤枉好 SQL。所以零误报纪律：**只核对带前缀且前缀能解析到真实表的引用**；无前缀列（多表歧义）、CTE 别名、表达式结果一律跳过；解析失败 fail-open；schema 读不到整层静默。

**代价**：CTE/子查询产出的列、无前缀歧义列核对不到（漏了有执行层兜底）。

**教训**：这层的误报率与规则误报率同级别重要——评测 --ci 30 题 cassette 全过零误伤后才敢挂载进 loop。
