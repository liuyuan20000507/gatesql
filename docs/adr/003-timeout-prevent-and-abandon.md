# ADR-003 · 查询超时靠「预防 + 放弃等待」，不靠 terminate()

**背景**：同步驱动 + 慢查询 = 服务假死，需要超时机制。

**决策**：组合拳——EQP 代价预检做**预防**（1ms 拦笛卡尔积）；超时后主线程**放弃等待**、标记 worker 污染、下次换新；容器 SIGKILL 兜底。

**关键问题**：实测 `worker.terminate()` 对卡在同步原生调用里的 worker **永不 resolve**（15 秒无反应，连 process.exit 都失效）。但主线程全程健康——所以 worker 隔离保的是可用性，不是超时本身。

**代价**：卡死的 worker 占内存到进程退出；优雅关闭失效，容器须配 SIGKILL 超时。

**教训**：被实测证伪的方案要留痕——这就是本文档存在的原因。
