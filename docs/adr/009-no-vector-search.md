# ADR-009 · 不用向量检索

**背景**：few-shot 召回和 schema 检索的常规做法是向量相似度。

**决策**：确定性的关键词 + 表名重叠打分 + 外键一跳闭包。

**关键问题**：**不是「4 张表用不上检索」这个浅层理由。真实理由：向量召回引入不确定性，同一道评测题两次跑出不同上下文，准确率变化再也无法归因——它会摧毁整个评测体系。** 「为了可评测性主动放弃更花哨的技术」，这个取舍本身比技术选择更体现工程成熟度。

**代价**：召回质量弱于语义检索；表大幅增长后需要换方案。

**对冲**：裁剪函数第一天就存在且可关闭——「表涨到 300 张怎么办」是能回答的。
