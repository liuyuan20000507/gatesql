# ADR-018 · trace 表结构第 2 周一次定死

**背景**：trace 是 3 周错题归因、4G 回放面板、CI 基线对比的共同地基，加字段很容易。

**决策**：`runs`/`steps`/`events` 表结构第 2 周定死；后续新增字段（如 receipt trace 的 attributes）只加在 JSON 的 attributes 列里，不动表结构。

**关键问题**：**每加一个字段都要重跑整套评测才能拿到可比数字**——表结构漂移会摧毁跨周对比。今天所有「本周 vs 上周」的对比表都建立在「表结构未变」这个前提上。

**代价**：早期没想到的维度（如 column_check）只能塞 attributes JSON，查询便利性打折。对冲：JSON 里键控访问，评测脚本统一解析。
