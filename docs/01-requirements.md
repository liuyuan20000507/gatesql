# 需求文档

## 一句话描述

用户用自然语言提问，系统自动生成 SQL、查询数据库、返回表格和图表，并用一段话解释结论。

## 为什么做这个

企业里最普遍的一类需求：业务人员想看数据，但不会写 SQL，只能排队等数据分析师。这个项目就是把「问一句话」和「拿到答案」之间的人力环节自动化。

## MVP 范围（第一个可用版本必须有的）

1. **提问** —— 输入框里用中文提问，例如「上个月销售额最高的 5 个商品是什么」
2. **展示过程** —— 界面上能看到系统当前在干什么（正在理解问题 / 已生成 SQL / 正在查询 / 正在总结），SQL 语句要展示出来给用户核对
3. **返回结果** —— 表格展示原始数据，自动选一种合适的图表，再加一段文字结论
4. **出错能自愈** —— SQL 执行报错时，把错误信息喂回模型让它改，最多重试 3 次，全失败才告诉用户
5. **只读保护** —— 任何 `INSERT` / `UPDATE` / `DELETE` / `DROP` 都必须被拦住，不能执行

## 明确不做的（防止无限膨胀）

以下这些**第一个版本一律不做**，想做就写进 `docs/backlog.md` 等以后：

- 用户注册登录（先用单用户，不做权限系统）
- 连接用户自己的数据库（先只查项目自带的示例数据库）
- 多轮追问的上下文继承（「那再看看前十名」这种先不支持）
- 导出 Excel / PDF
- 移动端适配

## 用户故事和验收标准

每条都必须能手动验证通过，才算这个功能做完了。

| 编号 | 用户故事 | 验收标准 |
|---|---|---|
| US-1 | 我提一个简单问题，能看到答案 | 输入「一共有多少个客户」，界面依次显示状态、SQL、表格、结论，全过程不超过 15 秒 |
| US-2 | 我能看到系统在思考 | 提问后 1 秒内界面出现状态提示，不是干等一片空白 |
| US-3 | 我能核对 SQL 对不对 | 生成的 SQL 完整展示在界面上，带语法高亮，可以复制 |
| US-4 | 涉及趋势的问题能看到图 | 输入「每个月的销售额趋势」，返回折线图；输入「各分类销售额对比」，返回柱状图 |
| US-5 | 系统写错 SQL 时能自己改对 | 故意问一个容易写错的问题，日志里能看到重试记录，最终返回正确结果 |
| US-6 | 恶意问题被拦住 | 输入「删除所有订单」，系统拒绝执行并说明原因，数据库数据行数不变 |
| US-7 | 问了数据里没有的东西，有合理回复 | 输入「员工工资是多少」，系统回答数据库里没有相关表，而不是编一个答案或报错崩掉 |

## 怎么衡量做得好不好

这是这个项目最有价值的部分，也是简历上唯一能写出数字的地方。

建一个测试集 `data/evalset.jsonl`，每行一条：

```json
{"id": 1, "question": "一共有多少个客户", "expected_sql_result": [[500]], "tags": ["简单计数"]}
```

**目标：50 道题，覆盖这些难度层次**

- 简单计数和求和（10 题）
- 带时间筛选（10 题）
- 需要 JOIN 两张以上表（10 题）
- 分组 + 排序 + 取前 N（10 题）
- 容易出错的坑（10 题）：比如问题里的说法和字段名不一致、需要处理 NULL、时间跨年

**评分方式**：对比执行结果而不是对比 SQL 文本，因为同一个问题有很多种正确写法。

**要记录的数字**：
- 准确率 = 结果正确的题数 / 总题数
- 平均重试次数
- 平均响应时间

每次优化后重新跑一遍，把数字变化记进 `docs/eval-log.md`。这份记录就是你面试时最有说服力的材料。
